# Задача: экономичный векторный бэкенд для Dear ImGui (перехват примитивов)

## Цель проекта
Использовать Dear ImGui и его immediate-mode подход без изменений API для пользователя,
но сделать его экономичным по ресурсам (CPU/GPU/энергопотребление):
- не рисовать, когда ничего не происходит;
- не рисовать, если кадр не изменился;
- перерисовывать только изменившиеся области;
- рендерить векторно (через высокоуровневые примитивы, а не треугольники ImGui).

В перспективе два бэкенда: нативный (ThorVG) и веб (WASM + TypeScript, Canvas 2D + текст в DOM).
Текущая задача касается только нативной части.

## Принятые архитектурные решения (не пересматривать без согласования)
1. **Форк Dear ImGui с точечными правками**, подключённый как git-сабмодуль.
   - Ветка `master` (не docking; multi-viewports не нужны).
   - Правится ТОЛЬКО `imgui_draw.cpp`. `imgui.h`, `imgui.cpp`, `imgui_widgets.cpp`,
     `imgui_tables.cpp` не трогать.
   - Правки — макросы-хуки в начале функций ImDrawList, по образцу хуков test engine:
     по умолчанию раскрываются в `(false)`, то есть без нашего конфига форк ведёт себя
     бит-в-бит как оригинал. Пример:
     ```cpp
     #ifndef IMGUI_DRAWLIST_HOOK_RECT_FILLED
     #define IMGUI_DRAWLIST_HOOK_RECT_FILLED(dl, a, b, col, r, f) (false)
     #endif
     void ImDrawList::AddRectFilled(...) {
         if (IMGUI_DRAWLIST_HOOK_RECT_FILLED(this, p_min, p_max, col, rounding, flags)) return;
         ... // оригинальный код без изменений
     }
     ```
   - Определения макросов живут в нашем репозитории, в `my_imgui_config.h`,
     подключаемом через `IMGUI_USER_CONFIG`.
   - Патч оформлять так, чтобы его можно было отправить PR-ом в upstream:
     минимальный, механический, 1–2 коммита, легко ребейзится.
2. **Перехват на уровне ImDrawList** — через него рисуют все виджеты и Render*-функции.
3. **Рекордер**: для каждого ImDrawList (хук получает `this`) ведётся компактный поток
   высокоуровневых команд (RectFilled, Rect, Line, Circle(Filled), Ngon, Triangle(Filled),
   Bezier, Polyline, ConvexFilled, пути с сохранением дуг/безье, Text, Image,
   RectFilledMultiColor → градиент, Push/PopClipRect, Push/PopTexture, Callback).
   У каждой команды при записи вычисляется bbox.
4. **Полнота семантики обязательна**:
   - поддержать каналы `ImDrawListSplitter` (Split/SetCurrentChannel/Merge), иначе
     ломаются таблицы и колонки;
   - всё, что не перехвачено (прямая запись вершин через PrimReserve/PrimWriteVtx/PrimRectUV,
     ShadeVerts*), должно попадать в fallback-команду `Mesh` **на своём месте в порядке
     команд**. Ни один пиксель, который нарисовал бы ImGui, не должен пропасть.
   - хук возвращает bool: `false` = «не перехвачено, работай как обычно» — это позволяет
     внедрять перехват постепенно.
5. **Тонкий интерфейс рендерера** (`renderer.h`), по семантике близкий к Canvas 2D API:
   fillRect/strokeRect со скруглением, path (moveTo/lineTo/arc/bezier), fill/stroke,
   linear gradient, pushClip/popClip, drawImage, drawText, measureGlyph.
   Движок должен заменяться реализацией одного файла. Первая реализация — ThorVG.
6. **Текст**: единый источник метрик. ImGui раскладывает текст по своим метрикам (ImFont,
   тот же TTF-файл), движок рисует тем же TTF без хинтинга, с выключенными кернингом и
   лигатурами. Обязателен тест совпадения: ширины `CalcTextSize` против измерений движка
   на большом наборе строк (латиница, кириллица, цифры, пунктуация). Если расхождения
   неустранимы — рисовать глифы по позициям, вычисленным по advance из ImFont
   (деталь реализации внутри рендерера).
7. Платформа окна/ввода — стоковый `imgui_impl_glfw` (или SDL), без изменений.

## Структура репозитория
```
third_party/imgui/        ← сабмодуль: форк, ветка drawlist-hooks
src/imgui_ext/
  my_imgui_config.h       ← определения макросов → вызовы рекордера
  recorder.h/.cpp         ← потоки команд, каналы, clip/texture stack, fallback-меш
  renderer.h              ← интерфейс рендерера
  renderer_thorvg.cpp     ← реализация на ThorVG
  diff.h/.cpp             ← (этап 4) сравнение кадров, dirty rects
examples/demo/main.cpp    ← окно с ImGui::ShowDemoWindow()
tests/                    ← тест метрик текста, сравнение со стоковым рендером
```
Сборка: CMake. ThorVG подключить сабмодулем или через FetchContent, собрав только нужные
модули (без SVG/Lottie-загрузчиков, если они не нужны). Проверить актуальный API ThorVG и
ImGui по их текущим версиям, не полагаться на память.

## Задача сейчас: этапы 0–3

### Этап 0. Базовые замеры
Стоковый ImGui + GLFW + OpenGL3, открыт ShowDemoWindow. Измерить и записать в
`docs/benchmarks.md`: CPU и GPU в простое, CPU и GPU при движении мыши, время кадра на CPU,
память. Описать методику, чтобы замеры можно было повторить.

### Этап 1. Цикл по событиям (стоковый ImGui, без патчей)
- ожидание событий (`glfwWaitEventsTimeout`), после события прогон 2–3 кадров;
- не засыпать, пока `io.WantTextInput` (мигающий курсор) или есть активная анимация;
  API для пользователя: «запросить перерисовку».

Критерий: CPU в простое около 0%, поведение UI не отличается от стокового.

### Этап 2. Пропуск одинаковых кадров
Хеш/сравнение ImDrawData с предыдущим кадром; при совпадении пропускать рендер и present.
Учесть пользовательские текстуры (счётчик версии).

### Этап 3. Хуки + рекордер + ThorVG с полной перерисовкой
- форк ImGui: составить полный список функций `imgui_draw.cpp`, требующих хуков, с
  пометкой «обязательно для demo» / «можно на fallback»; реализовать хуки;
- рекордер с каналами, clip/texture stack и fallback-мешем;
- рендерер на ThorVG, пока перерисовывающий весь кадр;
- тест метрик текста;
- визуальное сравнение: скриншот ShowDemoWindow со стоковым рендером против нашего
  (попиксельный diff с допуском на различия сглаживания); отчёт о расхождениях.

Критерий: все окна и виджеты демо отображаются корректно, включая таблицы, ColorPicker,
деревья, InputText, попапы; при выключенном конфиге форк идентичен upstream.

## Следующие этапы (не делать сейчас, но учитывать в дизайне)
- **Этап 4**: diff потоков команд по ImDrawList → dirty rects (объединение старого и нового
  bbox, учёт z-порядка окон, исчезнувших окон, слияние прямоугольников), replay только в
  dirty rects на постоянной поверхности, частичный present. Отладочный режим подсветки
  dirty rects.
- **Этап 5**: веб-бэкенд. Тот же рекордер в WASM, поток команд читается из памяти WASM
  через DataView, TS-рендерер: слой (div + canvas) на каждое окно ImGui, текст в DOM-span'ах,
  метрики из `measureText` через EM_JS, стабильные ключи узлов через хуки test engine
  (ItemAdd/ItemInfo), позже ARIA-роли.
  Поэтому формат команд должен быть плоским и сериализуемым (без указателей).

## Ограничения
- Не удалять код из ImGui (только добавлять хуки); оптимизацию размера бинарника не делать.
- Не использовать хаки восстановления примитивов из треугольников.
- При сомнениях в архитектурных решениях — остановиться и спросить, а не менять решение.
